# Domain Brief Task Reference

This document defines what should be included in the domain brief task that the design architect writes and hands off to the research assistant.

## What to include

- The client's initial request.
- Instructions to use web search for domain research.
- Instructions on how to access any specific data or resources the client has provided for this engagement.
- How to produce a domain brief covering:
  1. Domain structure, how the market/field/industry is organized, major segments, standard classification systems (NAICS, NCES, etc.)
  2. Sources of heterogeneity, factors that drive meaningful variation in the likely outcome variable (geographic, scale, channel, temporal, quality tier, regulatory, etc.) with mechanisms explained
  3. Known data sources, government databases, industry associations, reference sources, aggregator platforms, etc., with coverage and granularity notes.
  4. Domain-specific pitfalls, selection biases, measurement issues, definitional ambiguity, common confounds, etc.
  5. Suggested stratification variables, ranked by expected impact, with rationale, suggested levels, and data availability assessment.
- The output path that the assistant should write their work to. Ensure it's within the project's `engagement/domain/` folder.
- A target length of 300-500 lines -- enough to be informed, not a literature review
- Instructions on how the assistant can communicate with you for clarification, direction, or if they're having tooling issues.
- Instructions that your assistant should contact you when they have completed their work.
